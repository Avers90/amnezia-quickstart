# 6. Свой DNS: AdGuard Home

Нужен только при `awg_local_dns: true` (полный вариант).

Зачем:

- DNS-запросы клиентов не уходят к провайдеру и не идут мимо туннеля
- блокировка рекламы и трекеров сразу на всех устройствах
- статистика запросов по клиентам

## Установка

Второй хеш пароля в `vault.yml` (если ещё не добавили):

```bash
make hash
make vault-edit     # vault_adguardhome_pass_hash: "$2y$12$..."
```

```bash
make dns HOST=vpn1
```

AdGuard Home слушает **только IP туннеля** `10.66.0.1`: порт 53 (DNS) и 3000
(веб-интерфейс). Из интернета его не видно, только из VPN.

Запросы наружу идут по DoH/DoT (Cloudflare, Google, Quad9), провайдер VPS их
не видит.

Ставьте AdGuard Home **до создания клиентов**: в конфиг клиента записывается
`DNS = 10.66.0.1`, и без AdGuard Home сайты у него открываться не будут.

## Веб-интерфейс

Подключитесь к VPN и откройте <http://10.66.0.1:3000>. Логин равен `admin_user`.

## Фильтры

По умолчанию включены два списка:

- AdGuard DNS filter
- AdAway Default Blocklist

Остальные можно добавить в интерфейсе: «Фильтры» → «Чёрные списки DNS».

Если фильтр сломал нужный сайт (чаще всего банковские приложения), есть два
способа:

- в интерфейсе: «Журнал запросов» → найти заблокированный домен → «Разблокировать»
- через Ansible в `group_vars/awg/main.yml`, затем `make dns`:

```yaml
adguardhome_user_rules:
  - '@@||example.com^$important'
```

## Без своего DNS

Если AdGuard Home не нужен:

```yaml
## local.yml
awg_local_dns: false
```

Затем `make vpn HOST=vpn1`. Новые клиенты получат `DNS = 1.1.1.1`. У уже
созданных клиентов DNS в конфиге не меняется: его надо поправить в панели и
скачать конфиг заново.
