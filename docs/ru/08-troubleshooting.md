# 8. Если что-то не работает

## Первая проверка на сервере

```bash
ssh vpnadmin@203.0.113.10
sudo awg show awg0
```

Для каждого клиента (`peer`) смотрите на две строки:

- `latest handshake`: когда клиент последний раз успешно подключился.
  Если строки нет, клиент не подключался ни разу
- `transfer`: сколько данных передано

## Клиент не подключается

Смотрим, доходят ли пакеты клиента до сервера:

```bash
sudo tcpdump -ni any udp port 27015 or udp port 443 or udp port 51820
```

И подключаемся с клиента.

| Что видно | Значит | Что делать |
|---|---|---|
| Пакетов **нет совсем** | трафик режется по дороге: блок IP или порта | попробовать порт 443 в `Endpoint`; проверить с другой сети (Wi-Fi ↔ мобильный); если не помогло — [IP заблокировали](#ip-сервера-заблокировали) |
| Пакеты есть, `latest handshake` не появляется | сервер не принимает handshake | проверить, что конфиг скачан с этого сервера после последнего `make params`; обновить приложение (конфиг 2.0 требует свежий клиент) |
| Пакеты есть, на мобильном не работает, на Wi-Fi работает | DPI оператора режет конкретный вид пакетов | попробовать порт 443; сменить версию конфига, пока клиентов мало ([раздел 4](04-amneziawg-wgdashboard.md#параметры-менять-нельзя)) |

## Подключено, но сайты не открываются

| Признак | Причина | Что делать |
|---|---|---|
| Ничего не открывается, `ping 1.1.1.1` с клиента работает | DNS | `awg_local_dns: true`, а `make dns` не запускали — запустить |
| Ничего не открывается, ping тоже нет | нет NAT | `make firewall HOST=vpn1`, затем проверить `sudo iptables -t nat -S \| grep MASQUERADE` |
| Мелкие сайты открываются, крупные страницы висят | MTU | MTU в конфиге клиента 1376; попробовать 1280 |
| Отдельные сайты не открываются | блокировка в AdGuard Home | «Журнал запросов» → разблокировать домен |

## IP сервера заблокировали

Симптомы: со всех клиентов у одного оператора пакеты до сервера не доходят
(tcpdump пустой), а через другую сеть всё работает.

Варианты:

1. **Запасной порт 443** в `Endpoint`. Помогает, если режут порт, а не IP
2. **Новый IP у того же провайдера.** Многие продают дополнительный IP.
   Если в конфигах клиентов домен
   ([раздел 4](04-amneziawg-wgdashboard.md#домен-вместо-ip-по-желанию)),
   достаточно поменять A-запись, и клиенты после переподключения попадут на
   новый IP. Если в конфигах IP, всем придётся скачать конфиг заново
3. **Новый сервер у другого провайдера.** Иногда у оператора заблокирована
   вся подсеть хостера, и новый IP у того же провайдера не помогает

## Плейбук завис

> [!NOTE]
> На `WGDashboard` установка 5–10 минут идёт без вывода: собирается
> веб-интерфейс. Это нормально.

Если сборка идёт дольше 30 минут, плейбук завершится с ошибкой. При
обновлении панель откатывается на прежнюю версию и продолжает работать. Лог
сборки на сервере: `/opt/WGDashboard/src/log/install.txt`.

## Сломалось после ручных правок на сервере

Ansible приводит сервер к описанию в репозитории. Ручные правки правил
iptables пропадут при следующем `make firewall`. Безопасно посмотреть, что
изменится, можно так:

```bash
make vpn HOST=vpn1 CHECK=1
```

## Полезные команды

```bash
sudo systemctl status awg-quick@awg0     # AmneziaWG
sudo systemctl status wg-dashboard       # панель
sudo systemctl status AdGuardHome        # DNS
sudo journalctl -u wg-dashboard -n 50    # логи панели
```
