# 9. Секреты и безопасность репозитория

Если вы сделали форк или храните свою копию в git, личные данные не должны
туда попасть. Репозиторий устроен так, что всё личное лежит в файлах из
`.gitignore`.

## Что никогда не коммитится

| Файл | Что внутри |
|---|---|
| `ansible/inventory/hosts.yml` | IP ваших серверов |
| `ansible/inventory/group_vars/all/local.yml` | имя пользователя, SSH-ключ, белый список IP |
| `ansible/inventory/group_vars/all/vault.yml` | хеши паролей |
| `ansible/inventory/host_vars/` | параметры маскировки серверов |
| `ansible/.vault_pass` | пароль от vault |
| `*.conf`, ключи | конфиги клиентов, ключи |

В git лежат только `*.example` с выдуманными значениями (IP из
документационных диапазонов `203.0.113.0/24`, `198.51.100.0/24`).

Почему параметры маскировки тоже секрет: по ним строится DPI-сигнатура
вашего сервера. Опубликовали — облегчили блокировку.

## Защита от случайного коммита

```bash
pip install pre-commit      # или: brew install pre-commit
pre-commit install
```

Перед каждым коммитом запускаются:

- [gitleaks](https://github.com/gitleaks/gitleaks): ищет ключи и токены
- `scripts/check-secrets.sh`: блокирует личные файлы, приватные ключи,
  ключи WireGuard, хеши паролей, публичные SSH-ключи, незашифрованные
  `vault_*`, параметры маскировки и реальные IP в inventory

Те же проверки запускаются в GitHub Actions на каждый push.

Проверить весь репозиторий вручную:

```bash
scripts/check-secrets.sh
```

## Если секрет всё-таки попал в git

Удалить файл новым коммитом **недостаточно**: он остаётся в истории.

1. Считайте секрет скомпрометированным и замените его:
   - пароль панели или AdGuard: `make hash` → `make vault-edit` → `make vpn` / `make dns`
   - SSH-ключ: создать новый, заменить в `local.yml`, `make init` больше не
     сработает (root закрыт), поэтому добавить ключ на сервер вручную, старый
     удалить из `~/.ssh/authorized_keys`
   - параметры маскировки: только новый сервер или перевыпуск всех клиентов
   - конфиг клиента: удалить клиента в панели, создать нового
2. Затем почистить историю ([git filter-repo](https://github.com/newren/git-filter-repo))
   и сделать force push. Копии, которые уже успели скачать, это не удалит

## Vault

`vault.yml` зашифрован AES-256, ключ лежит в `ansible/.vault_pass`.

```bash
make vault-view     # посмотреть
make vault-edit     # изменить
```

Храните `.vault_pass` в менеджере паролей. Потеряли его — создайте новый
`vault.yml` из примера и заново сгенерируйте хеши: сами пароли на сервере
от этого не изменятся, пока вы не запустите плейбук.
